# SmartKitchen 2.0

Прошивка для существующей ESP32 и ILI9341 320×240. Распиновка сохранена: TFT SCK18/MOSI23/CS22/DC21/RST17/подсветка16, зуммер14, DHT21 GPIO25, PIR26, протечки39/34/35, MQ2 GPIO32, MQ135 GPIO33. Названия: водоподключение / стиральная машина / холодильник. Сверьте их с реальной проводкой.

## Подключение с телефона

При первом запуске появляется `SmartKitchen-XXXXXX`. Пароль из 16 символов отображается внизу TFT и в Serial Monitor (115200). Подключитесь к этой сети, откройте http://192.168.4.1, Веб-пульт открывается без логина и пароля. На домашнем роутере доступны http://smartkitchen.local или IP из Serial Monitor. При успешном подключении к роутеру резервная сеть выключается через минуту. Если Wi-Fi пропадёт, резервная точка включается через 20 секунд. Пароль сохраняется после перезапуска.

В пульте можно настроить домашнюю сеть, экран, Telegram и загрузить обновление. Пустой пароль сети сохраняет прежний; для открытой сети есть отдельная галочка. Изменения записываются во flash только по кнопке сохранения.

## Telegram

Прежний токен из исходника не используется. После его отзыва в BotFather введите новый токен, ID чата и числовой ID владельца в пульте. Сначала отправьте боту `/start` в Telegram. В личном чате chat ID и owner ID обычно совпадают. Для группы обязателен конкретный owner ID: остальные участники не могут выполнять команды.

После проверки токена прошивка удаляет прежний webhook, чтобы сообщения не продолжали отправляться на ранее заданный сервер. Ожидающие входящие сообщения при этом не удаляются. Этот бот должен использоваться только одним экземпляром прошивки; конкурирующий getUpdates нужно остановить отдельно.

Команды: `/start`, `/help`, `/check_kitchen`, `/status`, `/beep`, `/standby10`, `/standby60`, `/wake`. Чужие сообщения молча отбрасываются. Разрешённые команды ограничены по частоте. TLS проверяет корневой сертификат; Telegram ожидает корректное сетевое время. Проверка getMe отличает рабочий токен от недоступного API; при ошибке повтор через минуту.

Тревоги отправляются независимо от входящих команд. Есть повторные попытки, сообщение восстановления и напоминания об активной тревоге раз в 5 минут. Очередь хранит до 16 переходов состояния в RAM плюс отправляемое событие. При переполнении удаляется самое старое неотправленное событие. После отключения питания очередь теряется. Уведомления не заменяют локальную сирену.

## Локальная работа

Датчики и зуммер обслуживаются отдельной задачей с приоритетом выше экрана и HTTP. Telegram работает на другом ядре. Локальные протечки, температурная/влажностная тревога и сирена работают без Wi-Fi. Любая активная тревога удерживает общий сигнал; исправный датчик не выключает тревогу другого.

Протечка: включение от 10%, выключение до 5% включительно, подтверждение 500 мс. Усреднение 8 ADC-измерений. Температурная тревога от 35 °C, восстановление до 33 °C; влажность от 85%, восстановление до 80%. Ошибка DHT отображается отдельно и может отправляться в Telegram. Последнее значение не выдаётся за свежее.

MQ показываются как ADC, **не как ppm и не как измеренный CO₂**. Предварительное ожидание 180 секунд не заменяет первоначальный прогрев и калибровку по документации конкретного датчика. Сырые тревожные пороги 804/851 соответствуют прежнему пересчёту порога 3500, но не являются подтверждёнными концентрациями. На период прогрева газовая тревога по MQ не оценивается; протечки и DHT продолжают работать. Проверить реальные выходные напряжения и совместимость с ADC ESP32 необходимо на оборудовании.

Обрыв пассивного датчика протечки, дающий то же напряжение, что сухой датчик, нельзя надёжно отличить программно. Нижний предел ADC отмечается как «проверить» и не отменяет тревогу воды. Для контроля обрыва нужны изменения электрической схемы.

## OTA и защита

По просьбе владельца пульт и API доступны без логина и пароля участникам локальной сети. Запросы изменения и загрузки требуют специальный заголовок, проверку Host и Origin. Это защита от посторонних веб-страниц и DNS rebinding, а не авторизация участников вашей сети. Пароли/токены не возвращаются через status API. Доступ рассчитан на доверенную локальную сеть: HTTP не шифрует трафик, поэтому не пробрасывайте порт в интернет. Пароль резервной WPA-сети не хранится в JavaScript.

Первое обновление этой версии — USB. Далее в пульте выбирается **SmartKitchen.ino.bin**. Нужны стандартные разделы ESP32 4 MB с двумя OTA-слотами. Полный образ flash, bootloader и partitions через пульт не загружаются. OTA проверяет точный размер, ESP32 image header, встроенную метку SmartKitchen:ESP32:layout-v2 и целостность образа средствами Update. При активной тревоге загрузка отклоняется; появление тревоги во время записи отменяет обновление. Текущая прошивка остаётся рабочей при оборванной загрузке.

**Криптографическая подпись прошивки, Secure Boot и шифрование NVS не реализованы.** Участник локальной сети может изменить настройки и загрузить образ с совместимой меткой. Автооткат после неудачного запуска не гарантируется стандартным загрузчиком; вызов подтверждения старта совместим с загрузчиком, где rollback включён, но сам его не включает. При проблеме после успешной записи восстановление — по USB из резервной копии.

Во время записи flash возможны короткие системные паузы; отдельная задача снижает зависимость датчиков от HTTP, но это не прошивка с гарантированным временем реакции. Сам перезапуск на несколько секунд останавливает измерения.

## Сборка

Плата `esp32:esp32:esp32`, flash 4 MB, стандартные разделы. Core **3.3.5**. Библиотеки: DHT sensor library **1.4.7**, Adafruit ILI9341 **1.6.3**, Adafruit GFX **1.12.6**, Adafruit BusIO **1.17.4**, Adafruit Unified Sensor **1.1.15**, UniversalTelegramBot **1.3.0**, ArduinoJson **6.21.5**. Остальные сетевые библиотеки входят в core.

При необходимости скопируйте secrets.example.h в secrets.h и задайте начальную сеть. Этот файл исключён из Git. Секреты сети будут встроены в бинарник, если заданы этим способом; готовые бинарники и резервные копии не следует публиковать.

`logic_tests.cpp` проверяет во время компиляции все 64 сочетания тревог, границы сирены, монотонность и пределы ADC-преобразования для всех 4096 значений трёх датчиков, гистерезис, подавление коротких импульсов, переход millis через ноль и ночное расписание через полночь.

Аппаратная приёмка: каждую протечку отдельно при нормальных остальных датчиках; обрыв DHT; потерю и восстановление Wi-Fi; корректные места датчиков; уведомления и восстановление без входящих команд; запрет чужих команд; сон/пробуждение; OTA с правильным и неправильным образом; длительную работу с контролем heap. Полнота выполненной проверки записывается отдельно в отчёте поставки.
