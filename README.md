# SmartKitchen 2.1.0

Прошивка для существующей ESP32 и ILI9341 320×240. Распиновка сохранена: TFT SCK18/MOSI23/CS22/DC21/RST17/подсветка16, зуммер14, DHT21 GPIO25, PIR26, протечки39/34/35, MQ2 GPIO32, MQ135 GPIO33. Названия: водоподключение / стиральная машина / холодильник. Сверьте их с реальной проводкой.

Текущий выпуск: **2.1.0**. Владелец установил его через веб-OTA и подтвердил, что обновление работает. Подробности выпуска — в [RELEASE-2.1.md](RELEASE-2.1.md).

Отдельная пошаговая инструкция для владельца: [как собрать проект и получить BIN для веб-OTA](BUILDING.md).

## Экран и управление яркостью

- TFT: три строки протечки, температура с °C, влажность с %, одна общая шкала воздуха, анимированный человечек PIR и IP-адрес. Единицы привязаны к ширине числа; после движения значок PIR остаётся видимым 3 секунды. Вместо сырых MQ-чисел на TFT показывается `LUFTBELASTUNG`.
- В веб-пульте ползунок яркости сразу включает предпросмотр, без нажатия «Сохранить». Запросы объединяются с задержкой 120 мс; flash при перемещении ползунка не записывается.
- Предпросмотр будит экран и на 30 секунд перекрывает ночной режим и таймер сна. Затем возвращается обычное расписание. Кнопка «Сохранить» записывает выбранные настройки и также включает предпросмотр на 30 секунд.
- При активной тревоге экран не засыпает, а яркость составляет не менее 70%. Эта защита имеет приоритет над предпросмотром.
- По умолчанию: дневная яркость 65%, ночная 15%, ночь 22:00–07:00 по времени Германии, сон через 60 секунд без движения. Ночной режим требует корректного сетевого времени. В режиме резервной точки доступа экран автоматически не гаснет.
- Статус пульта показывает эффективную яркость и её причину: ручной режим, ночь, предпросмотр, сон или тревога; доступны состояние PWM, duty и частота через status API. Подсветка GPIO16 использует отдельный PWM-таймер, канал 2, 1000 Гц / 8 бит; зуммер GPIO14 — канал 0, 5000 Гц / 8 бит.

## Подключение с телефона

При первом запуске появляется `SmartKitchen-XXXXXX`. Пароль из 16 символов отображается внизу TFT и в Serial Monitor (115200). Подключитесь к этой сети, откройте [http://192.168.4.1](http://192.168.4.1). Веб-пульт открывается без логина и пароля. На домашнем роутере доступны [http://smartkitchen.local](http://smartkitchen.local) или IP из Serial Monitor. При успешном подключении к роутеру резервная сеть выключается через минуту. Если Wi-Fi пропадёт, резервная точка включается через 20 секунд. Пароль сохраняется после перезапуска.

В пульте можно настроить домашнюю сеть, экран, Telegram и загрузить обновление. Пустой пароль сети сохраняет прежний; для открытой сети есть отдельная галочка. Настройки из пульта записываются во flash при сохранении или явной фиксации базы воздуха; перемещение ползунка яркости включает только предпросмотр.

## Воздух: одна шкала MQ2 / MQ135

Шкала из пяти звёзд — **относительное изменение сигналов датчиков**, а не измеренные ppm, CO₂, официальный AQI или заключение о безопасности воздуха. MQ2 и MQ135 обрабатываются отдельно: общий результат берёт худшую оценку двух каналов, без усреднения. Даже сильную реакцию одного датчика нельзя скрыть спокойным показанием другого.

### Один раз зафиксировать базу

1. Проветрите помещение. Не должно быть дыма, паров приготовления пищи или бытовой химии.
2. После включения дождитесь 3 минут программного прогрева и не менее 30 секунд стабильного сигнала. Это не заменяет первоначальную выдержку и подготовку датчиков по документации производителя.
3. Откройте раздел «Воздух» веб-пульта, подтвердите условия чистого воздуха и нажмите **«Зафиксировать базу воздуха»**.

До фиксации базы TFT показывает `Basis im Web setzen`, а звёзды не выводятся. Базы обоих датчиков сохраняются в NVS, переживают перезагрузку и обычное OTA-обновление. Они не подстраиваются автоматически: повторную фиксацию выполняйте явно после проверки условий. Кнопка недоступна при нестабильном сигнале; сервер дополнительно отклоняет фиксацию при прогреве, ошибке MQ, газовой тревоге или устаревшем измерении.

### Как вычисляется оценка

Исходный ADC каждого MQ усредняется по 8 измерениям, затем сглаживается. Считается положительный прирост сглаженного ADC в процентах относительно сохранённой базы; сигнал ниже базы считается нулевым приростом. Это относительное изменение ADC, а не процент газа.

| Прирост относительно базы | Звёзды |
|---|---|
| Менее 20% | ★★★★★ |
| 20–39% | ★★★★☆ |
| 40–74% | ★★★☆☆ |
| 75–124% | ★★☆☆☆ |
| От 125% | ★☆☆☆☆ |

Это начальные эвристические пороги, которые требуют наблюдений на конкретной кухне. Ухудшение оценки подтверждается 2 секунды, восстановление — 10 секунд; установка новой базы и обнаружение ошибки обрабатываются отдельно.

На TFT: `Basisniveau` для пяти звёзд, `Erhoeht` для трёх–четырёх, `Lueften` для одной–двух. Прогрев, ошибка MQ и газовая тревога показываются отдельным состоянием вместо звёзд. Наличие пяти звёзд само по себе не доказывает, что воздух безопасен.

В веб-пульте доступны исходные значения MQ2/MQ135, сохранённые базы и график последних 120 опросов. Сглаженные значения дополнительно доступны через status API. График собирается в браузере, пока страница открыта; после её перезагрузки история очищается. Показания и история не отправляются во внешнее облако интерфейсом пульта.

Относительная шкала не заменяет локальную газовую тревогу: существующие абсолютные ADC-пороги продолжают действовать независимо от базы и звёзд.

## Telegram

Прежний токен из исходника не используется. После его отзыва в BotFather введите новый токен, ID чата и числовой ID владельца в пульте. Сначала отправьте боту `/start` в Telegram. В личном чате chat ID и owner ID обычно совпадают. Для группы обязателен конкретный owner ID: остальные участники не могут выполнять команды.

После проверки токена прошивка удаляет прежний webhook, чтобы сообщения не продолжали отправляться на ранее заданный сервер. Ожидающие входящие сообщения при этом не удаляются. Этот бот должен использоваться только одним экземпляром прошивки; конкурирующий getUpdates нужно остановить отдельно.

Команды: `/start`, `/help`, `/check_kitchen`, `/status`, `/beep`, `/standby10`, `/standby60`, `/wake`. Чужие сообщения молча отбрасываются. Разрешённые команды ограничены по частоте. TLS проверяет корневой сертификат; Telegram ожидает корректное сетевое время. Проверка getMe отличает рабочий токен от недоступного API; при ошибке повтор через минуту.

Тревоги отправляются независимо от входящих команд. Есть повторные попытки, сообщение восстановления и напоминания об активной тревоге раз в 5 минут. Очередь хранит до 16 переходов состояния в RAM плюс отправляемое событие. При переполнении удаляется самое старое неотправленное событие. После отключения питания очередь теряется. Уведомления не заменяют локальную сирену.

## Локальная работа

Датчики и зуммер обслуживаются отдельной задачей с приоритетом выше экрана и HTTP. Telegram работает на другом ядре. Локальные протечки, температурная/влажностная тревога и сирена работают без Wi-Fi. Любая активная тревога удерживает общий сигнал; исправный датчик не выключает тревогу другого.

Протечка: включение от 10%, выключение до 5% включительно, подтверждение 500 мс. Усреднение 8 ADC-измерений. Температурная тревога от 35 °C, восстановление до 33 °C; влажность от 85%, восстановление до 80%. Ошибка DHT отображается отдельно и может отправляться в Telegram. Последнее значение не выдаётся за свежее.

В веб-пульте MQ показываются как ADC, **не как ppm и не как измеренный CO₂**; на TFT используется описанная выше относительная шкала. Предварительное ожидание 180 секунд не заменяет первоначальный прогрев и калибровку по документации конкретного датчика. Сырые тревожные пороги 804/851 соответствуют прежнему пересчёту порога 3500, но не являются подтверждёнными концентрациями. На период прогрева газовая тревога по MQ не оценивается; протечки и DHT продолжают работать. Проверить реальные выходные напряжения и совместимость с ADC ESP32 необходимо на оборудовании.

Обрыв пассивного датчика протечки, дающий то же напряжение, что сухой датчик, нельзя надёжно отличить программно. Нижний предел ADC отмечается как «проверить» и не отменяет тревогу воды. Для контроля обрыва нужны изменения электрической схемы.

## OTA и защита

По просьбе владельца пульт и API доступны без логина и пароля участникам локальной сети. Запросы изменения и загрузки требуют специальный заголовок, проверку Host и Origin. Это защита от посторонних веб-страниц и DNS rebinding, а не авторизация участников вашей сети. Пароли/токены не возвращаются через status API. Доступ рассчитан на доверенную локальную сеть: HTTP не шифрует трафик, поэтому не пробрасывайте порт в интернет. Пароль резервной WPA-сети не хранится в JavaScript.

Первую установку на старую прошивку без OTA выполняют по USB. Для перехода с SmartKitchen 2.0.0 на 2.1.0 USB не нужен: в веб-пульте выберите образ приложения [SmartKitchen-v2.1.0-OTA.bin](firmware/v2.1.0/SmartKitchen-v2.1.0-OTA.bin). При самостоятельной сборке образ приложения обычно называется **SmartKitchen.ino.bin**. Нужны стандартные разделы ESP32 4 MB с двумя OTA-слотами. Полный образ flash, bootloader и partitions через пульт не загружаются. OTA проверяет точный размер, ESP32 image header, встроенную метку SmartKitchen:ESP32:layout-v2 и целостность образа средствами Update. При активной тревоге загрузка отклоняется; появление тревоги во время записи отменяет обновление. Текущая прошивка остаётся рабочей при оборванной загрузке.

Порядок обновления: откройте раздел «Обновление прошивки», выберите BIN, подтвердите совместимость и дождитесь перезапуска. После загрузки проверьте версию **2.1.0** внизу TFT или в веб-пульте. Сеть, Telegram, настройки экрана и базы MQ сохраняются в NVS. Если OTA отклонено из-за активной тревоги, сначала проверьте датчики и причину тревоги.

Готовый OTA-файл: **1 238 064 байта**, SHA256 `f9d41c3612e4aadf6015832d1015043932116652f9c18958fae639687ad8b8c6`. Для OTA используйте именно образ приложения, не старый полный комплект из корня `firmware/`.

**Криптографическая подпись прошивки, Secure Boot и шифрование NVS не реализованы.** Участник локальной сети может изменить настройки и загрузить образ с совместимой меткой. Автооткат после неудачного запуска не гарантируется стандартным загрузчиком; вызов подтверждения старта совместим с загрузчиком, где rollback включён, но сам его не включает. При проблеме после успешной записи восстановление — по USB из резервной копии.

Во время записи flash возможны короткие системные паузы; отдельная задача снижает зависимость датчиков от HTTP, но это не прошивка с гарантированным временем реакции. Сам перезапуск на несколько секунд останавливает измерения.

## Сборка

Плата `esp32:esp32:esp32`, flash 4 MB, стандартные разделы. Core **3.3.5**. Библиотеки: DHT sensor library **1.4.7**, Adafruit ILI9341 **1.6.3**, Adafruit GFX **1.12.6**, Adafruit BusIO **1.17.4**, Adafruit Unified Sensor **1.1.15**, UniversalTelegramBot **1.3.0**, ArduinoJson **6.21.5**. Остальные сетевые библиотеки входят в core.

При необходимости скопируйте secrets.example.h в secrets.h и задайте начальную сеть. Этот файл исключён из Git. Секреты сети будут встроены в бинарник, если заданы этим способом; готовые бинарники и резервные копии не следует публиковать.

Проверенная сборка 2.1.0: **1 237 919 байт программы (94% раздела), 53 008 байт статической RAM (16%)**. Статическая RAM не отражает пиковый расход heap во время работы.

`logic_tests.cpp` проверяет во время компиляции все 64 сочетания тревог, границы сирены, монотонность и пределы ADC-преобразования для всех 4096 значений трёх датчиков, гистерезис, подавление коротких импульсов, переход millis через ноль, ночное расписание через полночь, границы звёзд, отсутствие оценки без базы и выбор худшего MQ-канала.

Аппаратная приёмка: каждую протечку отдельно при нормальных остальных датчиках; обрыв DHT; потерю и восстановление Wi-Fi; корректные места датчиков; уведомления и восстановление без входящих команд; запрет чужих команд; сон/пробуждение; OTA с правильным и неправильным образом; длительную работу с контролем heap. Полнота выполненной проверки записывается отдельно в отчёте поставки.

## Статус проверок

- Версия 2.0.0 была записана по USB на ESP32 с flash 4 MB; выполнены 18 HTTP-проверок пульта и защит запросов.
- Перед передачей 2.1.0 выполнена реальная сборка, проверены метка совместимости и размер OTA-образа, границы расположения единиц по GFX-шрифтам и JavaScript пульта: ошибки датчиков, предпросмотр яркости, подтверждение базы и общая шкала.
- После самостоятельной установки 2.1.0 через веб-OTA владелец сообщил: «всё работает». Это подтверждение эксплуатации владельцем, а не отдельный инструментальный протокол измерений.
- Калибровка MQ известными газовыми смесями, длительные испытания, контролируемые протечки и проверка всех аварийных сценариев этим сообщением не подтверждаются. Доставка Telegram отдельно не подтверждена.
